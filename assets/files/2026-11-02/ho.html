Size Coding & Demoscene Math

Computing Sines and Cosines with the Harmonic Oscillator

To compute sines and cosines in size coding (like 256-byte or 4KB intros), you can use a discrete harmonic oscillator, often called the Minsky circle algorithm or magic circle algorithm. Instead of calling expensive sin() or cos() instructions or storing lookup tables, you generate waves iteratively using just two additions and two multiplications per step.

How the Math Works

A continuous harmonic oscillator is governed by the differential equation x'' = −ω2x. When discretized using a modified Euler method (specifically, a symplectic Euler integrator), the update equations become:

xn+1 = xn + εyn
yn+1 = yn − εxn+1

Notice that the second line uses the newly updated xn+1 rather than the old xn. This small change keeps the determinant of the transformation matrix equal to 1, which preserves energy and stops the wave from spiraling outward or decaying to zero.

  • Initial state: Set x0 = 1 (cosine) and y0 = 0 (sine) to start at angle 0.
  • Step size (ε): Controls the frequency. For small angles, ε ≈ 2π / N, where N is the number of steps per full circle. More precisely, ε = 2 sin(π / N).
  • Phase shift: Because the updates are staggered by half a step, x and y are slightly off from a true 90° phase difference by ε / 2 radians. For small ε, this error is visually unnoticeable.

Size-Coding Implementations

1. C / GLSL (4KB Intros)

In shader or C-based intros, the algorithm reduces to two lines inside a loop. You can often fold the ε multiplication into bit-shifts if you work with fixed-point integers. 

// Floating point (e.g., GLSL or C)
float c = 1.0, s = 0.0;
float eps = 0.01; // Frequency step

for (int i = 0; i < 1000; i++) {
    c += eps * s;
    s -= eps * c; // Uses the new 'c'
    // Use 'c' (cos) and 's' (sin) here
}

2. Fixed-Point / Bit-Shift Trick (256-Byte Intros)

In extreme size coding (like x86 assembly), floating-point constants take up precious bytes. If you choose ε = 2−k, multiplication becomes a simple bit-shift (sar), eliminating the need for any constants or FPU/SSE instructions. 

// Integer fixed-point version (no floats, no multiplies)
int c = 1 << 16; // Initial radius = 65536
int s = 0;

for (int i = 0; i < 1000; i++) {
    c += s >> 6; // eps = 1/64
    s -= c >> 6;
}

3. x86 Assembly (16-bit / 32-bit DOS Intros)

Using 16-bit registers (ax for cosine, bx for sine), the entire sine/cosine generator takes only 8 bytes of machine code: 

; Initial setup: AX = 0x4000 (radius), BX = 0
loop_start:
    mov dx, bx      ; Copy sin
    sar dx, 6       ; dx = sin / 64
    add ax, dx      ; cos += sin / 64

    mov dx, ax      ; Copy updated cos
    sar dx, 6       ; dx = cos / 64
    sub bx, dx      ; sin -= cos / 64
    ; Repeat loop

Key Trade-offs & Tips

  • Stability vs. Precision: Because the symplectic update preserves area, the trajectory forms a slightly tilted ellipse rather than a perfect circle. As long as |ε| < 2, the orbit remains completely stable and will never blow up to infinity, even after millions of iterations.
  • Amplitude Scaling: The peak amplitude of y (sine) is slightly smaller than x (cosine) by a factor of √(1 − ε2 / 4). Keep ε small (e.g., ≤ 0.1 or bit-shifts of 4 or more) so the ellipse looks indistinguishable from a circle.
  • No Random Access: Unlike fsin/fcos or Taylor series approximations, you cannot jump to an arbitrary angle θ. This method works best for drawing circles, spirals, waveforms, or driving continuous time-based animations.
